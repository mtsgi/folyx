# 実機検証

FoldLabで計測値を記録し、実機のブラウザの動作を確かめる手順をまとめています。この資料は開発者向けにリポジトリ内で管理しており、公開ドキュメントサイトには掲載しません。

## Pixel 10 Pro Foldで確認したこと

2026年10月27日に通常表示を確認したところ、0.1.0では丸め誤差によってフォールバックしてしまう不具合が見つかりました。2件の記録は、当時のスナップショットも含めて[修正前のテストデータ](../../../packages/core/tests/fixtures/pixel-10-pro-fold-normal.json)として保存しています。

記録では、レイアウトビューポートが幅851px・高さ817pxなのに対し、ブラウザが返す2つの領域はそれぞれ幅426px・高さ817pxで、右端が1pxはみ出していました。Visual Viewportの倍率も`1.0001797676086426`と、1からわずかにずれていました。

この結果を受け、`abs(scale - 1) * max(viewport.width, viewport.height) <= 1`を満たす倍率のずれは、丸め誤差として扱うようにしました。`scale`が有限の正数であること、Visual Viewportのオフセットが0であること、寸法と外周の差が各辺1 CSS px以内であることも確認します。はみ出した部分だけを切り取り、幅426pxと425pxの2つの領域を返します。

10月28日には修正後のバージョンを実機で試し、[46件の記録](../../../packages/core/tests/fixtures/pixel-10-pro-fold-2026-10-28.json)を取得しました。46件すべてで、現在の実装が返すスナップショットと記録が一致しています。

| 記録された状態                     | 確認できた動作                                                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `continuous`、倍率1、オフセット0   | 852 × 721の領域を851 × 720に補正し、`layout: "single"`、`segments.source: "browser"`になる。                             |
| `folded`に変化、倍率1、オフセット0 | 426 × 721の2領域を426 × 720と425 × 720に補正し、`layout: "horizontal"`、`segments.source: "browser"`になる。             |
| ズームやパンの操作中               | `segments.source`は`fallback`に切り替わり、`availability.segments`は`available`のままになる。                            |
| 倍率1・オフセット0に復帰           | ブラウザから取得した2領域に戻る。                                                                                        |
| 最後の倍率が約1.00667              | 丸め誤差として扱う範囲を超えるため、フォールバックになる。終盤にはレイアウトビューポートの高さが720pxから817pxに変わる。 |

回帰テストでは、46件をそれぞれ再現するほか、記録の順に状態を切り替えて購読通知も確認します。公開する状態が変わらない間は通知が増えず、2領域への復帰やビューポートの高さの変化は通知に反映されます。元の計測値と、`scenario: "normal"`や`pixel10ProFoldVerified: false`などのメタデータは、そのまま保存しています。

今回確認できたのは、上の表にある動作です。キーボード表示や画面回転、折りたたみの全状態については、引き続き実機で確認する必要があります。なお、これらの検証がすべて終わる前でも、npmへの暫定公開は行えます。

## 実機で記録を取る

FoldLabのDevice inspectorを開きます。Environment notesには、機種名、Androidとブラウザのバージョン、計測日、関係する設定を記入します。ブラウザのバージョンは省略せずに残しておくと、後で記録を見返すときに役立ちます。

シナリオを選んで記録を開始し、確認したい操作を行います。表示が安定した後の値も記録してから停止し、JSONファイルを出力します。

| シナリオ     | 確かめたいこと                                                  |
| ------------ | --------------------------------------------------------------- |
| 通常表示     | レイアウトビューポートとVisual Viewportの寸法、領域の原点と境界 |
| ズームとパン | 倍率を変えたとき、表示位置をずらしたとき、倍率1に戻したときの値 |
| キーボード   | 開閉前後の値、入力欄の位置、viewportの設定                      |
| 回転         | 縦向きから横向きに変えたときと戻したときの値、領域の順序と隙間  |
| 折りたたみ   | 開いた状態・半折り・閉じた状態での、端末の姿勢と表示領域        |

キーボードの動作は、`resizes-visual`・`resizes-content`・`overlays-content`の各設定で試します。FoldLabでviewportのmetaタグの設定を切り替え、ブラウザに実際に反映されたかも記録します。ズームは有効にしたまま、操作中と表示が安定した後の両方の値を残します。

境界を比較するときは、ブラウザによる1 CSS pxまでの丸め誤差を考慮します。元の計測値はそのまま残し、後から別の方法でも比較できるようにします。

出力するJSONには、ファイル形式とライブラリのバージョン、UA、メモ、イベントの時刻、ブラウザから取得したlayout・visual・segments、CSSで調べた4×4の範囲の計測値、Folyxのスナップショットが含まれます。APIが`available`でも、スナップショットの`segments.source`が`fallback`になる場合があります。これは、ブラウザから値を取得できたものの、その座標を安全に扱えず、代わりの領域を返したことを示します。

記録は端末内で扱い、外部には送信しません。FoldLabは最大1,000件の計測結果をメモリに保持し、上限を超えて古い記録を削除した場合は、その件数も出力します。

## 計測結果をテストに取り入れる

座標変換の対応を増やすときは、先に実機の記録をテストデータとして追加します。変換式と、その式を適用できる条件もまとめておくと、後の変更で不具合が起きていないか確かめられます。計測値が一致しない場合は、まず座標系の関係を確認します。寸法の比率から倍率を推測して合わせることはしません。

検証には次のコマンドを使います。

```sh
vp check
vp test
vp run -r build
vp run docs#validate
vp run test:package
```

これらのチェックで、APIから情報を取得できるか、フォールバックや領域の配置が正しいか、入力データを書き換えていないかを確認します。RAFを待たずに状態を読んだ場合や、購読を解除・再開した場合、SSRやhydration、複数箇所でインスタンスを共有した場合の動作も対象です。すべての検証をまとめて実行するには、`vp run ready`を使います。
