## 値の取得元を明確にする [#facts]

折りたたみ画面では、画面の形に応じてUIを配置できます。その判断に必要なのは、どのような情報を取得できていて、それがどこから来た値なのかを把握することです。Folyxは、値とその取得元をセットで返します。

値にはいくつかの種類があります。Providerが報告する姿勢は観測値です。layoutやgapsは、領域の座標から求める計算値です。フォールバックの領域は、計測値を使えないときに描画を続けるための代わりの値です。

たとえば、snapshotに領域が1つあっても、ブラウザの計測値なのか、viewport全体を覆うフォールバックなのかは、領域数だけではわかりません。`source`で値の取得元を、`availability`でAPIから情報を取得できたかを確認します。フォールバックの領域が1つあることから、物理的な画面数や、折りたためる端末かどうかを判断することはできません。

何が不明なのかも、アプリの判断に必要な情報です。Folyxは、不明な寸法やヒンジの角度、姿勢を推測で埋めません。`unknown`・`null`・フォールバックを区別して返します。

## 画面の使い方はアプリで決める [#geometry]

Folyxが表すのは、表示領域とその並び方です。読書画面にするか、一覧と詳細を並べるかは、アプリで決められます。gapは領域同士の隙間を表し、物理的なヒンジや、画面が隠れる部分とは限りません。

共通のレイアウト座標を使うため、Browser・Mock・独自のProviderを同じアプリのコードで扱えます。現在見えている範囲は別の情報として扱います。ズームやキーボード表示によって、公開する座標の基準が変わることはありません。

## Core・Vue・FoldLabで役割を分ける [#thin-core]

Coreでは、`getSnapshot()`で状態を読み取り、`subscribe()`で変化を追います。監視に必要なリソースは、購読の開始と解除に合わせて管理します。Vueアダプターはコンポーネントのライフサイクルとの連携を、FoldLabは計測値の記録・比較・実験を担当します。

Coreはフレームワークに依存せず、CSSの操作、テレメトリ、履歴の保存、端末固有の対応表は持ちません。役割を分けることで、それぞれの動作を確認しやすくしています。また、不変のsnapshotによって状態の変化を追いやすくし、テストで同じ条件を再現できるようにしています。

未知の姿勢は`unknown`、既存の分類に当てはまらない配置は`complex`として表します。新しいデバイスでも、取得できた領域をアプリへ渡せます。
