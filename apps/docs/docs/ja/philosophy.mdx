## 値の出どころを大切にする [#facts]

折りたたみ画面では、UIの配置にもいろいろな選択肢が生まれます。Folyx は、アプリが使える情報とその出どころを整理し、選びやすくすることを目指しています。

選択した Provider が返す姿勢のように、観測から得る値があります。layout や gaps のように、領域の座標から求める値もあります。フォールバックの領域は、計測値を使えないときにも描画を続けるための代わりの値です。

たとえば、snapshot に領域が1つある場合、それはブラウザの計測値かもしれませんし、viewport 全体を覆うフォールバックかもしれません。`source` を見ると、その違いがわかります。`availability` では、APIから情報を取得できたかを確認できます。単一領域のフォールバックだけで、物理的な画面数や折りたためる端末かどうかが決まるわけではありません。

`unknown` も、アプリが判断するための大切な情報です。Folyx は、わからない寸法やヒンジの角度、姿勢を推測で埋めず、`unknown`・`null`・フォールバックを、そのまま読み取れる形で返します。

## UIの使い方に余白を残す [#geometry]

Folyx が表すのは、領域とその並び方です。読書画面にするか、一覧と詳細を並べるか、別の使い方をするかは、アプリ側で選べます。gap は領域どうしの隙間で、物理的なヒンジや遮蔽領域とは限りません。

共通のレイアウト座標を使うことで、Browser・Mock・独自の Provider を、同じアプリのコードで扱えます。現在見えている範囲は別の情報として扱うため、ズームやキーボード表示で公開座標の意味が暗黙に変わることもありません。

## 役割を小さく分ける [#thin-core]

状態を読むときは `getSnapshot()`、変化を追うときは `subscribe()` を使います。必要なリソースは購読が管理します。Vue アダプターはコンポーネントのライフサイクルへつなぎ、FoldLab は計測値の記録・比較・実験を担います。

こうして役割を分けると、それぞれを確かめやすくなります。Core はフレームワークから独立し、CSS操作、テレメトリ、履歴の保存、端末固有の対応表を持ちません。不変の snapshot を使うことで、状態の変化を追いやすくし、テストでも同じ条件を再現しやすくしています。

状態の表現には、新しいデバイスを扱うための余地も残しています。知らない姿勢は `unknown`、新しい並び方は `complex` として表しながら、取得できた領域をアプリへ渡せます。
