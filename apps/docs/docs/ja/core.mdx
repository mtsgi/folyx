## インスタンスを作って状態を読む [#snapshots]

`createFolyx()`でインスタンスを作成します。デフォルトでは、ブラウザから情報を読み取るBrowser Providerを使います。Mockや独自のProviderを使う場合は、`createFolyx({ provider })`で指定します。

インスタンスには、現在の状態を読む`getSnapshot()`と、状態の変化を受け取る`subscribe(listener)`があります。各インスタンスは独立して動作します。Coreの利用にVueなどのフレームワークは必要ありません。

snapshotは、その時点の状態を表す読み取り専用のオブジェクトです。ネストしたオブジェクトも含めてfreezeされています。値・source・availabilityが変わらなければ同じ参照を返すため、参照の比較で変更の有無を確認できます。公開型は通常のオブジェクトで構成されており、DOMRectなどのブラウザ固有の型は必要ありません。

| フィールド       | わかること                                                                 |
| ---------------- | -------------------------------------------------------------------------- |
| `posture.value`  | 報告された姿勢。`continuous` / `folded` / `unknown`                        |
| `viewport.value` | レイアウト領域の幅・高さ（CSS px）。不明な場合は `null`                    |
| `segments.items` | レイアウト座標で表した領域。常に配列で返る                                 |
| `layout`         | 領域の並び方。`single` / `horizontal` / `vertical` / `complex` / `unknown` |
| `gaps`           | 整列した領域どうしの隙間。隙間がなければ `[]`、求められない場合は `null`   |
| `availability`   | 姿勢と segments のAPIから、現在情報を取得できるかどうか                    |

`horizontal`は、上端と高さが揃った領域が左右に並ぶ配置です。`vertical`は、左端と幅が揃った領域が上下に並ぶ配置です。どちらも領域の並ぶ方向を表し、ヒンジの向きを表すものではありません。領域はy、xの順に整列し、数は2つに限りません。Mockで領域を重ねたり、viewportの外に置いたり、不揃いに並べたりすると、`complex`になります。

## availability と source を読む [#availability]

値を使うときは、「APIから情報を取得できたか」と「その値をどこから取得したか」を確認します。この2つは別の情報です。

`availability`は、姿勢とsegmentsのAPIそれぞれについて、現在の取得状況を表します。

| availability  | 意味                                                                                            |
| ------------- | ----------------------------------------------------------------------------------------------- |
| `available`   | APIから現在の観測値を取得できた                                                                 |
| `unsupported` | ブラウザが対象のAPIを実装していない                                                             |
| `unavailable` | 現在の観測値を取得できない。SSR、取得例外、非アクティブなDocumentに対する `null` などが該当する |

`posture.source`・`viewport.source`・`segments.source`は、公開する値の取得元です。`browser` / `mock` / `provider` / `fallback` / `unknown`のいずれかになります。

たとえば、APIから領域を読み取れても、その座標を安全に変換できない場合があります。viewportの寸法が既知なら、`availability.segments`は`available`のまま、`segments.source`は`fallback`になります。APIの読み取りには成功したものの、描画には代わりの領域を使っているとわかります。

APIがFolyxの知らない姿勢を返した場合、姿勢の値は`unknown`になります。読み取りに成功していれば、availabilityは`available`のままです。姿勢と領域数は別々に扱い、領域数から姿勢を推測することはありません。

## 状態を読み、変化を受け取る [#notifications]

`getSnapshot()`は最新の状態を同期的に読み取ります。この呼び出しによって購読者へ通知されることはありません。`subscribe()`は現在の状態を同期的に1回渡し、その後の変化を通知します。戻り値は購読を解除する関数で、複数回呼んでも問題ありません。

Mockの変更は同期的に通知されます。BrowserのイベントはrequestAnimationFrame（RAF）でまとめるため、複数のイベントに対して、最新の状態が1回だけ通知されることがあります。

RAFの更新待ちの間も、`getSnapshot()`で最新値を読めます。その読み取りによって、既存の購読者への通知が失われることはありません。最後に渡した状態は購読ごとに管理するため、更新待ちの間に購読を始めた場合も、同じ状態を重複して通知しません。Browserでは途中の状態がまとめられることがあり、購読者には最新の状態が届きます。

最後の購読を解除すると、イベントの監視を終了し、予約済みのRAFをキャンセルします。再び購読すると最新値から監視を始め、以前の監視期間に登録されたコールバックは無効になります。一部の購読だけを解除した場合は、ほかの購読は続きます。

## SSRとフォールバック [#ssr]

`window`や`navigator`がない環境でも、import、インスタンスの作成、状態の取得、購読が可能です。

サーバーサイドレンダリング（SSR）では、両APIが`unavailable`、姿勢とlayoutが`unknown`、viewportが`null`、領域が空配列になります。viewportの寸法がわかっていてsegmentsを使えない場合は、viewport全体を覆う1つの領域をフォールバックとして返します。不明な寸法を推測せず、取得できた情報で描画を続けられます。

監視に必要なリソースは購読に合わせて管理されます。別途呼び出すdestroyメソッドや、共有のグローバルインスタンスはありません。
