## インスタンスを作って状態を読む [#snapshots]

まずは `createFolyx()` でインスタンスを作ります。既定では Browser Provider を使い、そのブラウザで取得できる情報を読み取ります。Mock や独自の Provider を使う場合は、`createFolyx({ provider })` で指定できます。

インスタンスには、その時点の状態を読む `getSnapshot()` と、変化を受け取る `subscribe(listener)` があります。インスタンスはそれぞれ独立していて、Core の利用に Vue などのフレームワークは必要ありません。

snapshot は、全体が freeze された読み取り専用のオブジェクトです。値・source・availability が同じあいだは参照も変わらないため、状態の変化を確かめるときにも使えます。公開型は通常のオブジェクトで構成されているので、DOMRect などのブラウザ固有の型を用意する必要はありません。

| フィールド       | わかること                                                                 |
| ---------------- | -------------------------------------------------------------------------- |
| `posture.value`  | 報告された姿勢。`continuous` / `folded` / `unknown`                        |
| `viewport.value` | レイアウト領域の幅・高さ（CSS px）。不明な場合は `null`                    |
| `segments.items` | レイアウト座標で表した領域。常に配列で返る                                 |
| `layout`         | 領域の並び方。`single` / `horizontal` / `vertical` / `complex` / `unknown` |
| `gaps`           | 整列した領域どうしの隙間。隙間がなければ `[]`、求められない場合は `null`   |
| `availability`   | 姿勢と segments のAPIから、現在情報を取得できるかどうか                    |

`horizontal` は、上端と高さが揃った左右の配置です。`vertical` は、左端と幅が揃った上下の配置を表します。どちらも領域の並びを表す名前で、ヒンジの向きではありません。領域は y、x の順に整列し、数は2つに限りません。Mock で重なり・範囲外・非整列の配置を指定すると、`complex` になります。

## availability と source を読む [#availability]

値を見るときは、「APIから情報を取得できたか」と「今使っている値はどこから来たか」を分けて考えると、状態を理解しやすくなります。

`availability` は、姿勢と segments のAPIそれぞれについて、前者を表します。

| availability  | 意味                                                                                            |
| ------------- | ----------------------------------------------------------------------------------------------- |
| `available`   | APIから現在の観測値を取得できた                                                                 |
| `unsupported` | ブラウザが対象のAPIを実装していない                                                             |
| `unavailable` | 現在の観測値を取得できない。SSR、取得例外、非アクティブなDocumentに対する `null` などが該当する |

`posture.source`・`viewport.source`・`segments.source` は、値の出どころを表します。値は `browser` / `mock` / `provider` / `fallback` / `unknown` のいずれかです。

たとえば、APIから領域を読み取れても、その座標を安全に変換できない場合があります。このとき `availability.segments` は `available` のまま、`segments.source` は `fallback` になります。APIが応答したことと、代わりの領域を使っていることを、両方読み取れるようにしています。

Folyx が知らない姿勢の値をAPIが返した場合は、値を `unknown` に揃えます。読み取りに成功していれば availability は `available` のままです。姿勢と領域数は別の情報として扱い、領域数から姿勢を推測することはありません。

## 状態を読み、変化を受け取る [#notifications]

`getSnapshot()` は最新の状態を同期的に読み取ります。この呼び出しだけでは、購読者への通知は行いません。`subscribe()` は現在の状態を同期的に1回渡し、その後の変化を通知します。戻り値は購読を解除する関数で、繰り返し呼んでも安全です。

Mock の変更は同期的に通知されます。Browser のイベントは requestAnimationFrame でまとめるため、いくつかのイベントから、最新状態の通知が1回だけ届くことがあります。

RAFの更新を待っているあいだも、`getSnapshot()` を呼べます。その読み取りによって、既存の購読者への変更通知が消えることはありません。購読ごとに最後に渡した状態を覚えているので、途中で購読を始めた場合も同じ状態を重複して通知しません。Browser の途中の状態はまとめられることがあり、購読者には最新の状態が届きます。

最後の購読を解除すると、イベントの監視と予約済みのRAFを解放します。再び購読するときは最新値から始まり、前の監視期間のコールバックは無効になります。一部の購読を解除しても、ほかの購読はそのまま続きます。

## SSRとフォールバック [#ssr]

`window` や `navigator` がない環境でも、import・生成・取得・購読を利用できます。

SSRでは、両APIが `unavailable`、姿勢と layout が `unknown`、viewport が `null`、領域が空配列になります。viewport の寸法がわかっていて segments を使えない場合は、その全体を覆う1つの領域をフォールバックとして返します。わからない寸法を補うことなく、手元の情報で描画を続けられるようにしています。

必要なリソースは購読が管理するので、別途呼び出す destroy メソッドや、共有のグローバルインスタンスはありません。
