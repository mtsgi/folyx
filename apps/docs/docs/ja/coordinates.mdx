## 同じ基準で座標を扱う [#contract]

座標をUIに使うときは、どこから測った値かがわかると扱いやすくなります。Folyx の viewport・segments・gaps は、レイアウトビューポートの左上を原点とする CSS px に揃えています。Browser Provider は `innerWidth` と `innerHeight` からレイアウトの寸法を読み取ります。

Visual Viewport は、ページのうち現在見えている範囲です。ズームやパン、キーボードの表示によって、その寸法や位置が変わることがあります。そのため、単位が同じ CSS px であっても、原点や座標系まで同じとは限りません。

Folyx は、矩形の境界に加えて座標系も確認します。寸法の比率や `devicePixelRatio`、`visualViewport.scale` から補正を推測せず、取得した値のスケールを保ちます。

## 0.1でのBrowserの取得方針 [#policy]

初期版では、レイアウトと Visual Viewport が一致する場合に、座標を変換せずそのまま使います。確認する条件は次のとおりです。

- Visual Viewport の scale が1であること。
- `offsetLeft` と `offsetTop` が0であること。
- 寸法の差が、ブラウザの丸めを考慮して1 CSS px以内であること。

矩形の境界は、これとは別に整合性を確認します。矩形が収まることだけを座標系の根拠にすることはなく、値の切り取りや数値の補正も行いません。

Visual Viewport を取得できない場合や、ズーム・キーボードなどで座標系が異なる場合、Browser Provider は生の矩形を公開状態へ渡しません。レイアウトの viewport が既知なら、その全体を1つのフォールバック領域として返します。viewport も不明なら、領域は空配列になります。生の領域を読み取れた場合のAPI availability は、`available` のままです。

0.1で対応しているのは、座標を変換せずに使える場合だけです。それ以外の座標変換は、まだ有効にしていません。Pixel 10 Pro Fold での動作も、実機では未確認です。端末名やUA文字列は、座標の変換規則には使いません。

## 変化を追い、計測値を比べる [#diagnosis]

Browser Provider は、window の resize、姿勢変更、画面回転、ページの復帰、visibilitychange、Visual Viewport の resize/scroll を監視します。Visual Viewport の計測値は、公開 snapshot には追加しません。

詳しく確かめたいときは、FoldLab でブラウザの生値と公開 snapshot を並べて記録できます。元の値を比較用に残しながら、Core ではレイアウト座標を扱えるようにしています。CSS の `env(viewport-segment-*)` も FoldLab での比較に使いますが、Core の取得経路には含めていません。

Browser Provider が使うのは、現行の `navigator.devicePosture` と `window.viewport.segments` です。旧 `visualViewport.segments` や `getWindowSegments` には対応していません。APIの検出とフォールバックにより、同じ利用コードを各ブラウザで動かせます。取得できる計測値は、それぞれのブラウザの対応状況によって変わります。

APIや座標系についてもう少し知りたいときは、[参考資料](/references)もご覧ください。
