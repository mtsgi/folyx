## 同じ基準で座標を扱う [#contract]

UIの配置に座標を使うには、どこを基準に測った値かを確認する必要があります。Folyxのviewport・segments・gapsは、レイアウトビューポートの左上を原点とするCSS pxで表します。Browser Providerは、`innerWidth`と`innerHeight`からレイアウトビューポートの寸法を読み取ります。

Visual Viewportは、ページのうち現在見えている範囲です。ズームやパン、キーボードの表示によって、大きさや位置が変わります。単位が同じCSS pxでも、レイアウトビューポートと原点や座標系が一致するとは限りません。

Folyxは、矩形が範囲内に収まるかだけでなく、座標系も確認します。寸法の比率、`devicePixelRatio`、`visualViewport.scale`から補正値を推測することはせず、取得した値のスケールを保ちます。

## バージョン0.1で扱えるブラウザの計測値 [#policy]

バージョン0.1では、レイアウトビューポートとVisual Viewportが一致する場合に、座標を変換せずに使います。次の条件をすべて確認します。

- Visual Viewportのscaleが1であること。
- `offsetLeft`と`offsetTop`が0であること。
- 寸法の差が、ブラウザの丸めを考慮して1 CSS px以内であること。

矩形の境界については、これとは別に整合性を確認します。矩形が範囲内に収まるという理由だけで、座標系が一致すると判断することはありません。矩形の切り取りや数値の補正も行いません。

Visual Viewportを取得できない場合や、ズーム・キーボード表示などで座標系が異なる場合、Browser Providerは生の矩形を公開状態へ渡しません。レイアウトビューポートの寸法が既知なら、その全体を1つのフォールバック領域として返します。viewportも不明なら、領域は空配列になります。APIから生の領域を読み取れていれば、availabilityは`available`のままです。

バージョン0.1が対応するのは、座標を変換せずに使える場合だけです。それ以外の座標変換は未対応です。Pixel 10 Pro Foldでの実機検証もまだ行っていません。端末名やUA文字列を使って座標の変換規則を決めることはありません。

## 変化を追い、計測値を比べる [#diagnosis]

Browser Providerは、windowのresize、姿勢の変更、画面の回転、ページの復帰、visibilitychange、Visual Viewportのresize/scrollを監視します。Visual Viewportの計測値は、公開するsnapshotには含めません。

計測値を調べるには、FoldLabを使います。ブラウザの生の値と公開snapshotを並べて記録できるため、元の値を残したまま比較できます。CSSの`env(viewport-segment-*)`もFoldLabでの比較に使いますが、Coreの情報源には含めていません。

Browser Providerが使うのは、`navigator.devicePosture`と`window.viewport.segments`です。旧APIの`visualViewport.segments`や`getWindowSegments`には対応していません。APIの検出とフォールバックによって、同じアプリのコードを各ブラウザで動かせます。取得できる情報は、ブラウザのAPI対応状況によって異なります。

APIや座標系の詳細は、[参考資料](/references)を参照してください。
