Providerは、姿勢や表示領域の情報をFolyxに渡すためのインターフェースです。ブラウザで計測した値も、テスト用に用意した値も、同じ方法で扱えます。

## Mockで画面の形を試す [#mock]

Mock Providerを使うと、折りたたみデバイスが手元になくてもUIの開発やテストができます。Browser Providerと同じインターフェースで利用でき、アプリの実行中に状態を変更することもできます。

```ts
import { createFolyx, createMockProvider } from "@folyx/core";
const mock = createMockProvider({
  posture: "folded",
  viewport: { width: 900, height: 600 },
  segments: [
    { x: 0, y: 0, width: 440, height: 600 },
    { x: 460, y: 0, width: 440, height: 600 },
  ],
});
const folyx = createFolyx({ provider: mock });
mock.set({ posture: "continuous" });
mock.set({ availability: { segments: "unsupported" } });
```

`set(patch)`は、指定した項目だけを更新します。省略した項目は変わりません。viewportやsegmentsを指定すると、その項目全体を置き換えます。入力はコピーされるため、渡したオブジェクトを後から編集してもProviderの状態には影響しません。

姿勢や`null`以外の領域を渡すと、availabilityを明示しない限り、その項目は`available`になります。`segments: null`のデフォルトは`unavailable`です。APIに未対応のブラウザを再現するには、`unsupported`を指定します。

APIの読み取りには成功しても、座標を変換できない状態も再現できます。`availability.segments: "available"`と`segments: null`を組み合わせます。viewportの寸法が既知なら、CoreはAPIの状態を`available`に保ちながらフォールバックを返します。

APIを`available`以外に切り替えると、その観測値はクリアされます。再び`available`にするときは、新しい値も渡してください。以前の値が意図せず使われるのを防ぐためです。領域が`available`のときの空配列、`NaN`や`Infinity`などの有限でない数値、0以下の寸法はエラーになります。エラーがある場合は更新全体が拒否され、変更前の状態が保たれます。

領域が重なる配置や、viewportの範囲外にある領域は指定できます。数値や寸法の検証を維持しつつ、`complex`な配置をアプリでどう扱うか試せます。

## 独自のProviderをつなぐ [#custom]

別の情報源を使うには、独自のProviderを実装します。必要なのは、同期的に状態を返す`getSnapshot()`と、購読の解除関数を返す`subscribe(listener)`です。

固定の状態を返す最小の例は、次のようになります。

```ts
import type { FolyxProvider, ProviderSnapshot } from "@folyx/core";
const reading: ProviderSnapshot = {
  source: "provider",
  availability: { posture: "unsupported", segments: "unavailable" },
  posture: "unknown",
  viewport: { width: 800, height: 600 },
  segments: null,
};
const provider: FolyxProvider = {
  getSnapshot: () => reading,
  subscribe: () => () => {},
};
```

Providerが通知するのは状態の変化だけで、購読直後の通知はCoreが行います。状態が変わる情報源では、変更時に最新値を通知してください。購読が解除されたら、Providerが登録したリスナーも解除します。

Providerが返すsegmentsは、Folyxの[レイアウト座標](/coordinates)に揃える必要があります。APIから取得できても安全に変換できない場合は、availabilityを`available`のままにして、segmentsに`null`を返します。フォールバックの処理はCoreに任せられます。診断用の生の計測値は、公開する状態とは分けて記録してください。
