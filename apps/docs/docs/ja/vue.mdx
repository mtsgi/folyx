`useFolyx()`を使うと、Folyxの状態に合わせてVueの表示を更新できます。パッケージを追加し、コンポーネントのsetup内で呼び出します。

<PackageInstall packages={["@folyx/core", "@folyx/vue", "vue"]} />

```vue
<script setup lang="ts">
import { useFolyx } from "@folyx/vue";
const { posture, layout, segments, snapshot } = useFolyx();
</script>

<template>
  <main>
    <p>{{ posture }} / {{ layout }}</p>
    <p>{{ segments.length }} regions</p>
    <p>{{ snapshot.availability.segments }}</p>
  </main>
</template>
```

posture・layout・segments・viewport・gaps・snapshotを、読み取り専用のcomputed refとして受け取れます。snapshotは`shallowRef`で保持し、不変のオブジェクトのままVueに渡します。Vue 3.5以降に対応しています。

## インスタンスを共有する [#sharing]

引数なしで`useFolyx()`を呼ぶと、呼び出しごとにCoreのインスタンスを作成します。`useFolyx({ provider })`でProviderを指定できます。既存のインスタンスを共有するには、`useFolyx({ folyx })`を使います。

```ts
const folyx = createFolyx({ provider: mock });
// 各コンポーネントのsetup内:
const state = useFolyx({ folyx });
```

引数なし、またはProviderを指定した場合、`useFolyx()`がCoreのインスタンスと購読を管理します。外部から渡されたProviderは呼び出し元が管理し、Vue側では破棄しません。

Folyxのインスタンスを共有した場合、各コンポーネントは自分が始めた購読だけを管理します。1つのコンポーネントが終了しても、ほかのコンポーネントや呼び出し元への通知は続きます。共有インスタンス自体は呼び出し元が管理します。`provider`と`folyx`は同時に指定できないため、どちらか一方を渡してください。

## SSRと初回描画の状態を揃える [#hydration]

サーバーサイドレンダリング（SSR）とクライアントの初回描画は、同じ初期値から始まります。姿勢とlayoutは`unknown`、APIは`unavailable`、viewportは`null`、領域は空配列です。共有インスタンスがすでに値を持っていても、この初期値を使います。SSR中に、そのインスタンスを読み取ったり購読したりすることはありません。

mount後に購読を始め、その時点の最新値をすぐに受け取ります。setupからmountまでの間に状態が変わっていても、最新の状態が反映されます。コンポーネントのscopeが終了すると、自分の購読を解除します。解除処理が複数回呼ばれても問題ありません。mountされなかったコンポーネントは購読を始めません。

SSRでインスタンスを共有するときは、リクエストごとに作成してください。利用者ごとに状態を分けるためです。Coreの寿命は購読と参照によって管理されるため、追加で呼び出すdestroyメソッドはありません。
